WoW Model Viewer - changes from pull request #18 to #98
=======================================================

Every pull request merged between #18 (19 August 2026) and #98 (10 October 2026), in order. Pull
requests that were closed without being merged are left out: #60, #61, #64, #65, #69 and #74. The
work of #61, #64, #65, #69 and #74 arrived later through #93 to #96. (#48, #49 and #80 are not pull
requests.) The FBX export features below (#63, #95, #96) are in the source code; the 1.0 installer
ships without the FBX exporter.

HIGHLIGHTS
----------

- A new viewport built on the Unity engine. It arrived step by step (#18 to #28), became the main viewport for
  creatures (#29) and then the only viewport, retiring the OpenGL one (#47).
- Models that look like they do in the game: new lighting and shadows (#30, #42, #58); transparent, glowing,
  animated and layered materials (#24, #33, #34, #37, #38, #41); particles and ribbon trails (#39); glowing eyes
  (#67); the game's own rules for world-model materials (#51).
- More than creatures: playable characters (#46), characters on mounts (#54, #56) and world models such as
  buildings (#50) in the viewport.
- New viewers next to Models: Textures, to browse, preview and export the game's textures (#71), and Buildings
  (#79). Browse lists what the current viewer shows (#72), and commands that only act on a model are greyed out
  elsewhere (#76).
- Classic clients open as themselves, with their own models, database and customization (#81, #83), and
  in Classic Beta characters can switch between their Classic and HD models (#84).
- Importing: Armory import works again and asks for region, realm and character name (#66, #68); NPCs and models
  load by ID (#78); NPCs on their own model show their weapons (#96).
- Equipment and animation: item sets by armor type (#73) and transmog sets with per-slot choices (#94), a working
  remove button on each slot (#93), sorting the animation list (#62), and choosing FBX export clips (#63, #95).
- Pictures: a one-click 4K screenshot with a transparent background (#59) and a choice of background colour (#77).
- A redesigned interface with a Dark appearance across the whole window (#44, #75), opening as a normal maximised
  window, now version 1.0 (#98).
- Faster and steadier: much faster client loading (#97) and model transfer to the viewport (#86), memory leaks
  fixed (#82, #91), and crashes fixed (#52, #70).

ALL MERGED PULL REQUESTS
------------------------

#18  2026-08-19  [Added]  New Unity viewport available from View > Unity Renderer
      - View > Unity Renderer opens a dockable pane with the new Unity-based viewport, the start of
        a new rendering pipeline that will replace the OpenGL viewport.
      - The Unity viewport draws straight from World of Warcraft game data. Nothing is exported, and
        no OBJ or FBX conversion step is needed.
      - At this stage the pane only shows a test cube with an orbit camera. The OpenGL viewport
        stays the main viewport while the migration continues.
      - The Unity viewport is optional. If no Unity renderer is installed next to the program (or at
        the path given in the settings), a clear message appears and the program carries on with the
        OpenGL viewport.

#19  2026-08-21  [Added]  The Unity viewport can read game files from the loaded client
      - While running, the Unity viewport asks the program for raw game files from the active
        client, on both modern (CASC) and older MPQ-based installs.
      - Whenever a model is loaded, the Unity viewport is told which model is on screen, and it
        shows the connection status in its pane. Models are not drawn yet.
      - Files travel directly between the program and the viewport and are never written to disk.
      - Damaged or truncated game files are now checked more strictly while being read, so they are
        less likely to cause crashes.

#20  2026-08-22  [Added]  The Unity viewport draws textured models
      - Models (M2) now appear in the Unity viewport as textured, unanimated meshes, with their
        textures decoded directly from the game's BLP files.
      - Creature skins are looked up in the game database. Older models with no database entry use a
        clearly marked fallback.
      - Parts the OpenGL viewport hides stay hidden, and reflective environment textures are
        applied, so the two viewports match on the first test models.
      - Animation, particles, characters, equipment and maps are not supported in the Unity viewport
        yet.

#21  2026-08-22  [Fixed]  The Unity viewport shows the skin you picked
      - Before, the Unity viewport used whichever creature skin the database listed first, so it
        could show a different skin from the one picked in the skin dropdown.
      - It now follows the dropdown, the skin chosen by the Random Skins option at load time, and
        the look applied by NPC import.
      - Textures picked one slot at a time from the folder skin lists are reflected too.
      - Changing the skin swaps only the textures that changed. The model stays in place and does
        not reload.

#22  2026-08-22  [Fixed]  Retail creature looks, geometry variants and particle colours load
      correctly
      - On current retail clients, creature display data was read from the wrong database columns.
        This affected both viewports.
      - Because of it, NPC and Armory import could not apply a specific creature look. The model
        kept whatever skin it already had, and the log reported that the display was not associated
        with the model.
      - Many creature looks also lost their geometry variants or picked up another look's geometry.
        Creature particle colour replacement never took effect.
      - Creatures whose looks differ only in geometry now list each variant separately in the skin
        dropdown, and particle colours apply where the creature defines them.
      - Older clients were not affected and behave as before.

#23  2026-08-22  [Added]  The Unity viewport shows the right geometry for each creature variant
      - Some creature variants differ in which parts of the model are shown rather than in their
        skin, for example a horse with a long flowing mane and tail versus a cropped mane and docked
        tail.
      - Before, the Unity viewport drew all such variants the same. It now shows and hides model
        parts exactly as the OpenGL viewport does.
      - Switching variants takes effect at once without reloading the model, and the camera does not
        jump.
      - Models without per-variant geometry look the same as before. Geometry driven by character
        customization or equipment is not covered yet.

#24  2026-08-22  [Added]  The Unity viewport draws transparent, glowing and layered materials
      - Before, the Unity viewport drew nearly every surface as opaque with a single texture. That
        was wrong for a large share of creatures.
      - Every M2 blend mode now works, including transparency, additive glow and cut-out edges,
        using the same rules as the OpenGL viewport.
      - Materials with a second texture layer now combine both layers, including
        environment-reflection layers. The few rare combinations still unsupported fall back to the
        first layer, as before.

#25  2026-08-22  [Added]  Models in the Unity viewport are now deformed by their bones
      - The Unity viewport now rebuilds each model's skeleton and deforms the mesh with it. This
        lays the groundwork for animation.
      - No animation plays yet. At rest, a model looks exactly the same as before.
      - Models whose bones are kept in a separate skeleton file are still drawn as a static mesh.

#26  2026-08-22  [Added]  Creatures play their idle animation in the Unity viewport
      - Creatures in the Unity viewport now loop their default standing idle. This is the same
        animation the OpenGL viewport picks, which is not always the model's first animation.
      - Parts that loop on their own timer, independent of the main animation, also move.
      - Rotations are interpolated smoothly, and models whose bones are kept in a separate skeleton
        file still stay static.

#27  2026-08-22  [Added]  The Unity viewport plays the animation you pick
      - Picking an animation such as Run, Death or an emote in the animation dropdown now switches
        the Unity viewport too. Before, it always played its own default idle.
      - The animation chosen while a model loads and the loop control also reach the Unity viewport,
        so it starts on the same animation as the app.
      - Some animations keep their keyframes outside the model file. For those, the viewport falls
        back to the model's idle and says why in the log, where before the model could break apart
        or fail to load.
      - Switching animation leaves the mesh, textures, materials and geoset selection as they were.

#28  2026-08-23  [Added]  The Unity viewport follows play, pause, speed and the frame slider, and
      plays animations from .anim files
      - Pause holds the Unity viewport on the same frame and resume carries on from there. The speed
        slider changes its speed and dragging the frame slider scrubs it.
      - Animations whose keyframes are stored in separate .anim files now play in the Unity
        viewport, as they already did in the OpenGL viewport. One example is Agronn's SitGroundDown,
        which did nothing before.
      - A new animation starts at once. The viewport no longer freezes for about a second after each
        change, and switching between animations no longer stutters.
      - As in the OpenGL viewport, looping effects such as a flickering torch keep running while the
        animation is paused.

#29  2026-08-23  [Changed]  Unity becomes the main viewport for creature models, and the program
      starts as an empty fullscreen viewer
      - Creature M2 models now show in the Unity viewport by default. Characters, WMOs and other
        files still use the OpenGL viewport. To switch back, untick View > "Unity as main viewport";
        the choice is remembered between sessions.
      - At startup the program opens fullscreen and loads nothing. It no longer asks for a client
        first: use File > "Load World of Warcraft" to open the client choice dialog.
      - The file tree, animation controls and character panel start hidden and can be shown from the
        View menu. Fullscreen keeps the menu bar, and F11 or Esc leaves it.
      - The viewport no longer shows a "Made with Unity" splash, status text or a spinning
        placeholder cube while it waits.
      (Screenshots and image sequences still render through the OpenGL viewport.)

#30  2026-09-03  [Changed]  New lighting for models in the Unity viewport, with cast shadows and
      contact shadows
      - Models are lit by a fixed, tuned light setup: a strong main light over a low ambient level,
        a soft fill and a narrow highlight that lands on bright painted details such as gold trim
        and gems.
      - The main light stays fixed to the world, so the lit side does not flip when you orbit the
        camera, and the underside stays dark when you look from below.
      - Models cast shadows on themselves, for example hoods on faces and reins on bodies. Cut-out
        parts cast shadows in their actual shape, and glowing or transparent parts cast none.
      - Glowing parts such as lanterns are no longer dimmed by the lighting.

#31  2026-09-04  [Internal]  Research report on how M2 models look in the Unity viewport compared
      with the OpenGL viewport
      - Adds a written audit of every visual system that affects how an M2 model looks, such as
        particles, texture animation and transparency. For each one it records what the old and new
        viewports do and how often it occurs across the game's models.
      - Adds a read-only command-line option that reports what a model file contains, which was used
        to survey the game's models. The viewport looks the same as before.

#32  2026-09-04  [Fixed]  Large models no longer draw the wrong triangles, and models without a
      selected variant no longer show every variant at once
      - On large high-detail models, parts of the mesh could draw triangles that belonged to other
        parts. The Unity viewport now reads those models correctly.
      - When no creature variant is selected, the Unity viewport now shows only the default geoset,
        as the OpenGL viewport does. Before, it drew every variant at the same time.

#33  2026-09-05  [Fixed]  Cut-out transparency, self-lit surfaces, texture tiling, reflections and
      see-through parts now render correctly in the Unity viewport
      - Cut-out parts such as leaves, hair and fringes are now transparent where their texture is.
        On the most common kind of cut-out surface they were drawn solid before.
      - Surfaces the model marks as unlit are no longer darkened or shaded by the viewport lighting.
      - Textures now tile or stretch at their edges as each texture specifies, instead of using one
        setting for all of them.
      - Reflective surfaces that use the first texture layer for their reflection now show it moving
        with the view, instead of fixed to the surface.
      - See-through parts now draw in a consistent order, the same order the OpenGL viewport uses.

#34  2026-09-06  [Added]  Animated materials play in the Unity viewport
      - Material animations stored in the model now play. Scrolling and scaling textures move on
        every surface; colour tints, fading opacity and texture blend weights apply to self-lit
        surfaces only for now (#38 adds tints on lit materials).
      - Parts that an animation fades out to nothing are hidden, the same way the OpenGL viewport
        hides them.
      - Material animation uses the same clock as the skeleton, so pause, scrubbing, speed and
        looping apply to it too.
      - Animated texture rotation is not applied yet.

#35  2026-09-06  [Internal]  Diagnostic options for checking the effect on Drakestalker's Trophy
      Pauldrons
      - Adds opt-in diagnostic options and extra log output that were used to check how the effect
        on Drakestalker's Trophy Pauldrons renders: drawing only chosen parts of a model, fixing a
        texture slot to a specific file, and listing the textures each part uses.
      - Rendering is unchanged when these options are not used.

#36  2026-09-06  [Fixed]  Head, shoulder, belt and hand-held items opened on their own show every
      part of their model
      - Opening a head, shoulder, belt or hand-held item now shows all of its model parts, as when a
        character wears it. For example, the upper flame plumes on Drakestalker's Trophy Pauldrons
        were missing before.
      - Items whose model is merged into the character (chest, legs, shirt, gloves, boots, cape) are
        unchanged and still open with only their base parts.
      - Loading a model with no skin choices now clears the previous model's part selection instead
        of carrying it over.
      - A new command-line option opens an item directly by its item ID, the same way the item
        dialog does.

#37  2026-09-07  [Fixed]  Glowing and unlit effects keep their full brightness in the Unity viewport
      - Glowing, additive and unlit material layers were being dimmed by a brightness curve that was
        only meant for the preview light. They now show the colour the model asks for.
      - Effects such as the eye glow and flame wisps on Drakestalker's Trophy Pauldrons are a little
        brighter. Ordinary lit surfaces look exactly as they did before.

#38  2026-09-09  [Fixed]  Glowing materials render as brightly as in the game
      - The Unity viewport's tone mapping and vignette are removed because they capped brightness so
        that nothing could reach full white. Bloom stays, and highlights and glows now look as hot
        as in the OpenGL viewport.
      - Textures are now blended the way the art was painted. The lighting was rebalanced to match,
        so models keep their shadow side.
      - Armour reflection textures now come from the game's own item material data. Before, they
        were guessed.
      - Glow layers that several material types had been dropping are back, with their authored
        pulsing, so embers and similar effects animate as intended.
      - Model colour tints now apply to lit materials as well as unlit ones.

#39  2026-09-10  [Added]  Particles and ribbon trails now appear in the Unity viewport
      - Before this change the Unity viewport drew no particle emitters or ribbon trails at all.
        They now appear, for example the Lich King's effects, phoenix trails and the glowing motes
        on raid weapons.
      - Particles follow the animation: they speed up or slow down with playback speed and stop when
        the animation is paused.
      - Gravity, colour, fading over a particle's life, and particle size are read the way the game
        stores them. Effects that came out broken or hugely oversized now look right.
      - Items that set their own particle colour now show that colour. The program had never applied
        it before.
      - Each emitter is drawn in one pass however many particles it has, so models with many effects
        stay smooth.

#40  2026-09-10  [Added]  The mouse wheel now zooms the Unity viewport
      - Scrolling the mouse wheel now zooms the Unity viewport. Before, the wheel did nothing there.
      - Each notch zooms by the same amount as in the OpenGL viewport, with a smooth glide. Zooming
        in and back out by the same number of notches returns exactly to where you started.
      - The zoom range follows the model's size, so you can zoom in close on small items and far out
        on very large models.
      - The camera can no longer pass through or flip around the model's centre, and zooming in
        close no longer cuts the model away.
      - The wheel only zooms while the pointer is over the viewport, and the first scroll is no
        longer ignored.

#41  2026-09-11  [Fixed]  Layered, see-through effect models look like they do in the game
      - Layered, translucent effect models look much closer to the game: brighter, more saturated
        and properly see-through. Algalon the Observer was the main test case.
      - Parts built as flat cards that always face the camera, such as Algalon's star flares and
        haloes, were invisible before and now appear.
      - Particles appear at their full density, tail-style particles draw as streaks along their
        path, and changing the animation no longer wipes existing particles.
      - See-through layers are drawn in the game's order, and particles and ribbons are drawn after
        the model so they no longer vanish under translucent bodies.
      - Stacked additive glow layers now reach full brightness instead of stopping short.
      (The contact-shadow changes merged into this branch are listed under #42.)

#42  2026-09-12  [Fixed]  Contact shadows in the Unity viewport are stable and soft
      - Contact shadows stay stable while zooming. Before, they switched themselves off as the
        camera came close.
      - Black wedges, striping and shadows cast across the model from far away are gone, and only
        surfaces that really touch are darkened.
      - Shadow edges are soft instead of hard straight lines.
      - Shadows are lighter, so the deepest contact areas no longer turn completely black.

#43  2026-09-12  [Fixed]  Model loading, animation switching and creature parts fixed in the
      embedded viewport
      - The whole window no longer blinks each time a model loads.
      - The camera now starts in front of the model and slightly above it, instead of behind it.
        Framing allows for the idle animation, so hovering creatures are no longer cut off at the
        top.
      - The animation no longer jumps or restarts about a second after a model appears.
      - Choosing another animation no longer freezes the model in its previous pose.
      - Creatures opened from the file list on current clients no longer lose parts such as Akama's
        hair and beard, in both viewports. Without a creature look to follow, they show the base
        mesh plus the first variant of each part group, not every variant at once.

#44  2026-09-13  [Changed]  Redesigned main window built around the viewport
      - The main window is rebuilt around the viewport. A command bar holds Open model, Reset
        camera, Screenshot, Fullscreen, the model's name and toggles for the Browse, Model and
        Animation panels. The status bar shows model counts.
      - File List is now Browse. It has a labelled search box with a clear button, a hint about the
        three-character minimum, result counts, and the file-type filter above the tree.
      - A new Model panel replaces the Character pane. It has Appearance (skins, texture overrides,
        character controls, WMO doodad sets), Geosets (a checkbox tree that also updates the Unity
        viewport) and Info tabs.
      - The Animation panel has a filterable clip list, Play/Pause, Stop, frame stepping, a scrubber
        and speed reset, with queue options in a collapsible section. The About menu is now Help,
        with a Keyboard Shortcuts list.
      - The OpenGL debug toggle no longer also saves view slot 1, F11 only toggles Fullscreen, and
        Open model is ignored while a client is still loading. Saved layouts from the old panes are
        reset once.

#45  2026-09-13  [Fixed]  Geoset checkboxes show and hide model parts in the Unity viewport straight
      away
      - Ticking or unticking a submesh in the Geosets panel updates the Unity viewport at once. The
        model is not reloaded, and the camera, animation, particles and ribbons are not reset.
      - Before this fix, base-mesh parts (geoset 0) and single parts that share an id with others
        could not be hidden, and the panel quietly reverted those clicks.
      - If the viewport refuses a change, the checkbox returns to its last confirmed state and the
        reason is shown. A waiting notice appears if the renderer does not answer.
      - The Unity renderer has to be updated along with the program. An older renderer refuses
        geoset clicks with a notice instead of ignoring them silently.

#46  2026-09-14  [Added]  Playable characters render in the Unity viewport
      - Characters no longer fall back to the OpenGL viewport. The Unity viewport shows them with
        their skin and eye textures, customization geosets, merged armour and attached items such as
        weapons and shoulders.
      - Characters animate in Unity, including the HD races, whose bones and animations are stored
        in separate skeleton files. Unity also plays alias animations such as EmoteTalkNoSheathe,
        which the OpenGL viewport did not.
      - Changes to appearance, equipment or geosets update the character in place. The body is not
        reloaded, the camera is not re-framed and the animation does not restart.
      - A character appears about one second after loading starts, and large model transfers to the
        renderer are faster for every model.
      - Not yet shown in Unity: mounted characters, secondary and mouth animations, and the
        per-model transform and transparency settings from Model Control.

#47  2026-09-14  [Changed]  Unity is the only viewport and the OpenGL viewport is retired
      - The Unity viewport is the centre pane from startup, and File > Reset Layout keeps it there.
        The "Unity as main viewport" toggle is gone, View > Restart Unity Renderer replaces View >
        Unity Renderer, and old saved layouts are reset once.
      - Content Unity cannot draw yet, such as images, world models and mounted characters, shows a
        notice in the viewport instead of switching to OpenGL. Renderer crashes and lost connections
        show a notice with a Restart button.
      - Removed OpenGL-only features: Save Screenshot (F12), Export Image Sequence, background
        colour and image, the Camera submenu, Set Canvas Size, lighting options, the Display
        settings page, Show/Zero Particle, and the matching shortcuts and command bar buttons.
      - Model Control is now View > Attachments... It keeps only the model/attachment choice and the
        Render and Scale settings for items attached to a character.
      - The Browse filter "Images (*.blp)" works again, and picking an image no longer opens a Save
        PNG dialog. OBJ and FBX exports still use the model's current animation pose.

#50  2026-09-14  [Added]  World models (WMO) render in the Unity viewport
      - Selecting a WMO keeps the Unity viewport active and draws the building's geometry and
        textures. The "cannot show world models" notice no longer appears.
      - This first step covers static geometry only: doodads, liquids, lights, fog, vertex-colour
        shading and sky are not drawn yet. Some modern WMOs draw white or with the wrong texture
        until the material update in #51.
      - Camera zoom and clipping scale with the size of the world model, and M2 framing comes back
        when a model is loaded again.
      - A WMO root whose name ends in a number (for example 11xt_rockbridge_003.wmo) now loads as
        itself when opened by path or FileDataID, instead of being mistaken for a group file; Browse
        did not list such roots until #79. A possible crash when closing the program after viewing a
        WMO is fixed.

#51  2026-09-15  [Changed]  World model (WMO) materials follow the game's own shader rules
      - Each WMO material is drawn by the rules of its shader type. Before this change, one texture
        was drawn on every surface.
      - Modern multi-layer surfaces show their real blended textures, such as rock with sandy paths
        or marble with gold trim. Before this change, they rendered white or were covered by an
        effect texture.
      - Vertex-colour two-layer blends, alpha-cutout materials, double-sided materials and texture
        clamping are handled.
      - Glow and environment-map effects, blend modes 2 and higher, and vertex-colour lighting are
        not drawn yet; these materials keep a simple fallback.
      - Heavily layered world models take a little longer to load and use more video memory, because
        their real layer textures are now loaded.

#52  2026-09-15  [Fixed]  Choosing "None" in the mount list no longer crashes the viewer
      - Choosing "None" in the mount list used to crash the viewer, whether or not a mount was up.
      - Dismounting hands the character back to the viewport without deleting it, and the Unity
        viewport shows the character again.

#53  2026-09-15  [Internal]  Research on remaining WMO material effects recorded, with no change to
      rendering
      - This change records what was learned about the game's blended WMO materials and
        glow/environment effects. How world models are drawn is unchanged.
      - It adds an opt-in diagnostic view that shows where glow effects would appear, plus more
        detailed per-material log lines for checking WMO materials.

#54  2026-09-16  [Added]  Characters can ride mounts in the Unity viewport
      - Choosing a mount no longer replaces the viewport with the "Mounted character" notice. The
        dressed character sits on the mount and keeps their equipment.
      - Rider and mount animate independently with their own animation choices, and the camera
        frames both of them.
      - Mounting, dismounting and switching mounts happen without reloading the character. A mount
        that cannot be built leaves the character on screen.
      - The mount uses its own textures, geosets and particle colours. A mount with no seat point
        carries the rider at its centre.
      - Changing equipment while mounted now updates the rider. Before this fix, it refreshed the
        mount.

#55  2026-09-16  [Fixed]  Model > Appearance offers the correct customization options for modern
      characters
      - Options and choices follow the game's requirements for race, class and earlier choices. For
        example, an Undead male lists all 11 Jaw Features and the Skin Type "Bony".
      - Skin Color, Face Features and Eyesight follow the choices they depend on. Dependent rows
        update after each change, and a choice that becomes invalid switches to the first valid one.
      - NPC-only options such as Eye Style no longer appear for player characters, and Death
        Knight-only choices are no longer offered to every class.
      - Changing a customization no longer leaves the previous face, scalp or eye texture on the
        character.
      - The cached game database is rebuilt once after the update. Known gaps: the default lower jaw
        stays visible under Jaw Features, and "Sockets" still shows the eye.

#56  2026-09-16  [Added]  Characters can be mounted, swapped and dismounted from a Mount card on
      Model > Appearance
      - A playable character's Model > Appearance page now starts with a Mount card: "Add a mount to
        this character" with Choose Mount, or the current mount's name with Change Mount and
        Dismount. It is hidden for creatures and world models.
      - Choose Mount and Change Mount open a floating, searchable mount list. Typing any part of a
        name filters it at once, and Up/Down with Enter or a click mounts right away with no OK
        step. Escape or a click outside closes it without changing anything.
      - The Appearance tab reads "Appearance · Mounted" while the character rides, and Character >
        Mount / Dismount stays in step with the card in both directions.
      - The section below the card is now titled "Character Appearance". The card replaces the old
        Mount / dismount button at the bottom of the page.
      - Fixed: long equipment item names no longer widen the Appearance panel past its edge. They
        now end in an ellipsis.

#57  2026-09-21  [Fixed]  Unity viewport fixes for white mounts, black item effects, jumping
      animations and flat particles
      - Some mounts and creatures, such as Primeval Skyfriend, drew white because their skin
        textures were lost on the way to the viewport. Their body, wings and saddle are now
        textured.
      - An item's blended effect, such as on Chosen Bloodslayer's Fanged Grips, no longer turns into
        a solid black rectangle after the item level is changed.
      - Equipping an item, changing a customization, opening View NPC, or picking, swapping or
        dismounting a mount no longer makes the animation jump back or restart. Swapping mounts
        keeps the rider's current riding animation.
      - Stretched particles, such as dripping effects, now hang along their direction of fall
        instead of lying as flat horizontal bars. Other camera-facing particles each get their own
        starting rotation.
      - The NPC list behind View NPC opens about four times faster.

#58  2026-09-21  [Changed]  Faces are lit, and shadows cast from a distance are softer in the Unity
      viewport
      - A soft front light from the camera now brightens faces and other surfaces that face the
        viewer. Before, faces looked grey and unlit next to bright shoulders.
      - Shadows cast from further away, such as a head's shadow on the neck and chest, are now soft
        and lighter instead of hard and stair-stepped. Close contact shadows stay crisp.
      - This is a deliberate look change. Models read somewhat flatter than before, and shadows on
        world-model platforms are paler.

#59  2026-09-21  [Added]  One-click 4K screenshot with a transparent background from the Unity
      viewport
      - A new Screenshot button on the command bar saves the current view as a 3840x2160 PNG with a
        transparent background. The Save As dialog suggests a name made from the model and the date
        and time.
      - The image is rendered at full resolution off-screen. It is not an upscaled grab of the
        window, so the result does not depend on the window size.
      - The capture uses the same camera, animation moment and particle state as the live view, and
